# Assignment 11 Reflection

The pipeline did not run cleanly on my first try. The first failure was due to a syntax error, which was easily corrected. Other failures were due to forgetting to split the returned probabilities and mislabelling a directory. All of these were simple fixes before finally getting a successful run. The prefect UI showed the failed and successful runs along with descriptive logs of each. The steps where the code broke were red and clearly stated the issue that caused the break. There were some task retries. When the directory name was incorrect, the task ran through its retries before stopping. 
For the most part, the LLM summaries are good and line up well with the model information. I tweeked the instructions a bit, and there is more focus on the confidence of the model. For example, 9-01 is marked as a bad day for running, but the reasons stated are uncertain conditions and a low prediction confidence. There could be more clarity in that statement as to what the uncertain conditions are without mentioning the model's confidence.
I would bring a little more clarity to the instructions with less emphasis on explaining the confidence of the model. However, I think a bigger change if I were to deploy this would be including the thresholds in the metadata in the user message to the LLM so as to bring a little more clarity as to what the user prefers in running days. Another change would be adjusting the model's threshold by finding a balance below 0.5 that catches closer to 90% of the good running days. As mentioned in a previous assignment, I would rather turn back than miss a good day.
